# HIG Gaps (Stage 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the HIG gaps found in review: a confirmed "Remove from Backlog", a VoiceOver-friendly rating, layouts that reflow at accessibility text sizes, context menus with previews, swipe-to-remove on Home, pointer hover and hardware-keyboard shortcuts on iPad.

**Architecture:** Pure decisions (copy, spoken labels, the accessibility-size threshold, the search-focus request) live in plain `.ts` modules with vitest tests. Rows and tiles become expo-router `Link`s with `Link.Trigger` / `Link.Preview` / `Link.Menu`; Home rows build their menu in a `BacklogGameRow` that owns the per-row mutations. Pointer hover and key commands are two small local Expo modules under `apps/mobile/modules/`.

**Tech Stack:** Expo SDK 57, expo-router 57 (`Link.Preview`, `Link.Menu`), react-native-gesture-handler 2.32 (`ReanimatedSwipeable`), `@expo/ui` SwiftUI, Expo Modules API (Swift), vitest.

**Spec:** `docs/superpowers/specs/2026-10-12-ipad-duo-adaptive-layout-design.md` §3 (Stage 2). Builds on Stage 1 (branch `feat/ipad-adaptive-layout`).

## Global Constraints

- Branch `feat/hig-gaps`, cut from `feat/ipad-adaptive-layout`.
- Status changes from menus only on Home rows; Search/Explore/Similar/Share lists get preview + Share only (spec §3.4 — summaries carry no rating, and the upsert would wipe it).
- Every status change goes through `useUpsertBacklogEntry` (haptic, §2.6a) and `wouldExceedSlots` (paywall gate).
- Every removal goes through `confirmRemove` — toolbar, context menu and swipe alike.
- `Link.Menu` must be a direct child element of `Link` (expo-router finds it by element type): build it with lowercase functions or inline JSX, never wrap it in a component.
- A row's `href` must stay stable while its preview is open.
- `isAccessibilitySize` threshold: `fontScale >= 1.6`.
- Anything under `apps/mobile/test/` must not import `react-native`, `@expo/ui`, `expo-*` or `modules/*`.
- Colours via `PlatformColor`; the only hex literal stays `Brand.tint`.
- Lint `--max-warnings 0`, Prettier, conventional commits.
- Read `https://docs.expo.dev/versions/v57.0.0/` before using an Expo API new to this repo (Expo Modules API, `requireNativeView`).

## Review Focus

1. **Tapping a row still navigates within its tab** (Home → `/game/[id]`, Search → `/search/game/[id]`, Explore and Similar → their tab's route, Share sheet → `/shared/game/[id]`) and a Similar Games tile pushes a new detail rather than replacing the current one (`push` on `Link`). Checked per call site in Task 4 and Task 9.
2. **A context-menu status change keeps the rating** and is blocked by the paywall gate exactly as `EntryActions` is. Pinned by passing `entry.rating` in Task 5's code and by the shared `wouldExceedSlots`; checked manually in Task 9.
3. **Cancelling a removal does nothing** — from the toolbar, the menu and the swipe (swipe closes back). Pinned by `removeConfirmCopy` tests (Task 1) and manual checks.
4. **VoiceOver never reads "black star"** — rows read "Playing, rated 9 out of 10", the rating button reads "Rating, 9 out of 10". Pinned by `format.test.ts` (Task 2).
5. **⌘F from another tab** switches to Search and focuses the field; **⌘F while already on Search** focuses it too. Pinned by `search-focus.test.ts` (Task 8).

```ts
export function ratingButtonLabel(rating: number | null): string {
  return rating === null ? "Rate" : String(rating);

export function ratingButtonSymbol(rating: number | null): SFSymbol {
```

- [ ] **Step 1: Implement** `backlog-game-row.tsx`:

```tsx
import type { BacklogListItemWire, BacklogStatus } from "@repo/contracts";
import { Link, useRouter } from "expo-router";

import {
  useBacklogStats,
  useDeleteBacklogEntry,
  usePremium,
  useUpsertBacklogEntry,
} from "@/api/hooks";
import { GameRow, type GameRowVariant } from "@/components/game-row";
import { STATUS_ORDER } from "@/features/backlog/sections";
import { activeSlotsUsed } from "@/features/backlog/slots";
import { confirmRemove } from "@/features/game/confirm-remove";
import { rowSubtitle, rowSubtitleSpoken, statusLabel, statusSymbol } from "@/features/game/format";
import { shareGame } from "@/features/game/game-menus";
import { wouldExceedSlots } from "@/features/paywall/should-offer-paywall";

/**
 * A Home row with the backlog's own menu. Home is the one list that knows each
 * game's entry, rating included — so it is the one list that may change status
 * without wiping the rating (spec §3.4).
 */
export function BacklogGameRow({
  entry,
  variant,
}: {
  entry: BacklogListItemWire;
  variant: GameRowVariant;
}) {
  const upsert = useUpsertBacklogEntry(entry.gameId);
  const remove = useDeleteBacklogEntry(entry.gameId);
  const premium = usePremium();
  const stats = useBacklogStats();
  const router = useRouter();
  const activeCount = stats.data === undefined ? undefined : activeSlotsUsed(stats.data);

  const setStatus = (next: BacklogStatus) => {
    if (next === entry.status) return;

    if (wouldExceedSlots({ premium, activeCount, from: entry.status, to: next })) {
      router.push("/paywall");
      return;
    }

    upsert.mutate({ status: next, rating: entry.rating });
  };

  const askRemove = () => confirmRemove(entry.game.name, () => remove.mutate());

  return (
    <GameRow
      href={`/game/${entry.gameId}`}
      title={entry.game.name}
      subtitle={rowSubtitle(entry)}
      spokenSubtitle={rowSubtitleSpoken(entry)}
      coverImageId={entry.game.coverImageId}
      variant={variant}
      menu={
        <Link.Menu>
          <Link.Menu title="Status" icon={statusSymbol(entry.status)}>
            {STATUS_ORDER.map((status) => (
              <Link.MenuAction
                key={status}
                icon={statusSymbol(status)}
                isOn={status === entry.status}
                onPress={() => setStatus(status)}
              >
                {statusLabel(status)}
              </Link.MenuAction>
            ))}
          </Link.Menu>
          <Link.MenuAction icon="square.and.arrow.up" onPress={() => shareGame(entry.game)}>
            Share
          </Link.MenuAction>
          <Link.MenuAction icon="trash" destructive onPress={askRemove}>
            Remove from Backlog…
          </Link.MenuAction>
        </Link.Menu>
      }
    />
  );
}
```

`backlog-screen.tsx` `renderItem`: the `game(entry, variant)` helper returns `<BacklogGameRow key={entry.gameId} entry={entry} variant={variant} />`; drop the now-unused `rowSubtitle` import.

- [ ] **Step 2:** `swipe-to-remove.tsx`:

```tsx
import { useRef, type ReactNode } from "react";
import { PlatformColor, Pressable, StyleSheet, Text } from "react-native";
import Swipeable, { type SwipeableMethods } from "react-native-gesture-handler/ReanimatedSwipeable";

import { Type } from "@/theme";

/**
 * A trailing "Remove" that asks first (`onRemove` goes through
 * `confirmRemove`). No full-swipe delete: a confirmation after a full swipe
 * feels broken. The row closes before the alert so a cancel leaves it tidy.
 */
export function SwipeToRemove({
  onRemove,
  children,
}: {
  onRemove: () => void;
  children: ReactNode;
}) {
  const swipeable = useRef<SwipeableMethods>(null);

  return (
    <Swipeable
      ref={swipeable}
      friction={2}
      rightThreshold={40}
      overshootRight={false}
      renderRightActions={() => (
        <Pressable
          style={styles.action}
          accessibilityRole="button"
```

```swift
/// its children the system highlight, shaped to the row or card.
class PointerHoverView: ExpoView, UIPointerInteractionDelegate {
  var cornerRadius: CGFloat = 0

  required init(appContext: AppContext? = nil) {
    super.init(appContext: appContext)
    addInteraction(UIPointerInteraction(delegate: self))
  }

  func pointerInteraction(
    _ interaction: UIPointerInteraction,
    styleFor region: UIPointerRegion
  ) -> UIPointerStyle? {
    let parameters = UIPreviewParameters()
    parameters.visiblePath = UIBezierPath(roundedRect: bounds, cornerRadius: cornerRadius)
    return UIPointerStyle(effect: .highlight(UITargetedPreview(view: self, parameters: parameters)))
  }
}
```

```ts
/**
 * ⌘F's hand-off to the Search route: it may be pressed on another tab, before
 * Search is focused and holding its search bar ref. A request either reaches
 * the listening route now or waits, once, for it to start listening.
 */
let pending = false;
let listener: (() => void) | null = null;

export function requestSearchFocus(): void {
  if (listener) listener();
  else pending = true;
}

export function onSearchFocusRequest(next: () => void): () => void {
  listener = next;

  if (pending) {
    pending = false;
    next();
  }

  return () => {
    if (listener === next) listener = null;
  };
}
```

```swift
import ExpoModulesCore
import UIKit

public class KeyCommandsModule: Module {
  fileprivate static weak var current: KeyCommandsModule?
  private var registered: [String: UIKeyCommand] = [:]

  public func definition() -> ModuleDefinition {
    Name("KeyCommands")
    Events("onKeyCommand")

    OnCreate {
      KeyCommandsModule.current = self
    }

    Function("register") { (id: String, input: String, modifiers: [String], title: String) in
      DispatchQueue.main.async {
        self.register(id: id, input: input, modifiers: modifiers, title: title)
      }
    }

    Function("unregister") { (id: String) in
      DispatchQueue.main.async {
        self.unregister(id: id)
      }
    }
  }

  /// The key window's root controller. Every focused responder's chain reaches
  /// it — a presented modal's through its presenter — so its commands work
  /// from anywhere in the app.
  private var root: UIViewController? {
    UIApplication.shared.connectedScenes
      .compactMap { $0 as? UIWindowScene }
      .flatMap { $0.windows }
      .first { $0.isKeyWindow }?
      .rootViewController
  }

  private func register(id: String, input: String, modifiers: [String], title: String) {
    unregister(id: id)

    let command = UIKeyCommand(
      title: title,
      action: #selector(UIViewController.barklogPerformKeyCommand(_:)),
      input: input == "escape" ? UIKeyCommand.inputEscape : input,
      modifierFlags: Self.flags(modifiers),
      propertyList: id
    )
    command.wantsPriorityOverSystemBehavior = true

    root?.addKeyCommand(command)
    registered[id] = command
  }

  private func unregister(id: String) {
    if let command = registered.removeValue(forKey: id) {
      root?.removeKeyCommand(command)
    }
  }

  fileprivate func fire(_ id: String) {
    sendEvent("onKeyCommand", ["id": id])
  }

  private static func flags(_ modifiers: [String]) -> UIKeyModifierFlags {
    var flags: UIKeyModifierFlags = []
    for modifier in modifiers {
      switch modifier {
      case "command": flags.insert(.command)
      case "shift": flags.insert(.shift)
      case "option": flags.insert(.alternate)
      case "control": flags.insert(.control)
      default: break
      }
    }
    return flags
  }
}

extension UIViewController {
  /// On every controller, so whichever one first sees the command in the
  /// responder chain can forward it.
  @objc func barklogPerformKeyCommand(_ sender: UIKeyCommand) {
    guard let id = sender.propertyList as? String else { return }
    KeyCommandsModule.current?.fire(id)
  }
}
```

```ts
import { useEffect, useEffectEvent } from "react";

import KeyCommands from "../../modules/key-commands";

export type KeyModifier = "command" | "shift" | "option" | "control";

/**
 * Registers a hardware-keyboard shortcut while `enabled`. Tab screens stay
 * mounted when hidden, so they pass `useIsFocused()` — two focused-looking
 * screens would otherwise fight over ⌘R. The title shows in iPadOS's ⌘-hold
 * overlay.
 */
export function useKeyCommand({
  id,
  input,
  modifiers = [],
  title,
  onPress,
  enabled = true,
}: {
  id: string;
  input: string;
  modifiers?: KeyModifier[];
  title: string;
  onPress: () => void;
  enabled?: boolean;
}): void {
  // An effect event, not a ref written during render: the latest `onPress`
  // without re-registering the command every render.
  const fire = useEffectEvent(onPress);
  const modifierKey = modifiers.join("+");

  useEffect(() => {
    if (!enabled) return;

    KeyCommands.register(id, input, modifierKey === "" ? [] : modifierKey.split("+"), title);
    const subscription = KeyCommands.addListener("onKeyCommand", (event) => {
      if (event.id === id) fire();
    });

    return () => {
      subscription.remove();
      KeyCommands.unregister(id);
    };
  }, [id, input, modifierKey, title, enabled]);
}
```
